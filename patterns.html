Design System · Patterns

Patterns

How components combine to solve a problem that recurs across screens - reach for one of these before assembling the same layout from scratch a second time.

Filter bar

The standard row above any filterable list or table. Free-text search first (the most common narrowing action), then structured filters in the order they're most likely to be used, then a way back out.

KPI row

Three to five headline numbers at the top of a dashboard, each with its own trend - never more than fits in one row before it starts requiring horizontal scroll.

Search + results

A search field with results updating beneath it. Below the field, exactly one of three things is visible at a time: matching rows, or an Empty state explaining why there are none - never a blank space that could be either.

Empty state layout

The zero-content state of any list, table or search result. Always explains why the space is blank and, where one exists, offers the single action that would fill it - never just "No data".
