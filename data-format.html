Data Format

Set consistent display rules for numbers, dates and data states. Preview your choices, then copy the guidance or download the configuration.

Numbers and currency

Format quantities consistently for the selected locale. Keep identifiers, phone numbers and postal codes as text to preserve leading zeros.

Thousands separator Use locale grouping by default. Indian grouping, decimal marks and digit shapes follow the locale; custom grouping must not conflict with decimal marks. –
Units Preserve unit-symbol case (kg, kW, °C). For SI quantities, choose a space or non-breaking space before the unit; no-space formatting is a project exception. –
Currency The locale controls symbol position and spacing. Choose a symbol, currency code or name. Decimal precision fixes the displayed currency fraction; it does not convert currencies. –
Percentages Pass a ratio: 0.125 means 12.5%. Locale controls the percent sign and spacing. Never multiply the value twice. –
Large amounts Compact notation follows locale conventions. Use standard notation for exact comparisons. The expanded example below uses the selected decimal precision. –Expanded:
Tables Use tabular numerals and consistent alignment. End alignment is recommended for numeric columns; text identifiers keep their text alignment. –

Dates and times

Keep calendar dates separate from timestamps. Date-only values retain their calendar day; timestamps are displayed in the selected time zone.

Absolute date Choose YYYY-MM-DD for shared, unambiguous dates, or a locale or long date for readers in a known locale. This example is a date-only value. –
Absolute time Choose a 12- or 24-hour clock for your audience. Include seconds only when needed. This timestamp is 14:08 UTC before conversion. –
Combined The selected separator joins the display date and time. A T separator alone does not produce an ISO timestamp; use explicit-offset timestamps for data interchange. –
Relative time When enabled, use localized seconds, minutes or hours for events within 24 hours, then an absolute date. When disabled, always show the date. –
Time zone Use an IANA zone such as Asia/Kolkata. Show the zone when readers work across regions. Daylight-saving rules apply to the timestamp’s date. –
Ranges Provide two valid dates in chronological order. The separator is configurable. Date-only endpoints remain unchanged in every time zone. –

Missing and sensitive data

Use distinct states for zero, absent values, pending requests and errors. Masking is presentation only: remove sensitive data before delivering it to the browser.

Zero A real zero is a value. Never replace it with the missing-value placeholder. –
No value Use the configured placeholder for a confirmed absent value. An empty list instead needs a clear message such as “No results”. –
Loading Use a skeleton or loading text while a request is pending. Announce loading once for the containing region, rather than every table cell. Loading…
Invalid value Validate inputs before formatting and show a specific error. The formatter falls back to the missing placeholder for invalid input, so callers must preserve the error state. Invalid date — check the source value
Empty list A completed search with no matches is an empty state, not a missing cell or a loading request. No results. Try a different search.
Full redaction Replace every character with the chosen mask. Do not reveal the original value in tooltips, accessible names or exported content. –
Partial redaction Reveal only the permitted trailing characters (0–8); at least one character always stays masked. The configured default controls generic redaction. –
Default redaction This example follows the Full or Partial default selected above. Use only fictional data in examples. –

Implementation contract

Saved validated choices override project recommendations, which override system defaults. This implementation contract governs static specimens. Resolved tokens in the current export are authoritative values. Component exceptions must name the affected role and reason.

Flow

Configure a field, inspect its formatted example, copy/export current valid settings and reset/reload. Every valid input updates without blur. Invalid simultaneous fields all expose errors and retain the prior valid configuration.

Constraints

Decimal precision 0–6, trailing reveal 0–8, one Unicode code point for the mask, a supported locale and valid IANA zone. Explicit comma grouping cannot conflict with a comma decimal locale. Distinguish real zero, missing, invalid and loading. Never reveal the entire value through a tooltip or accessible name.

Layout and accessibility

Group number/currency, date/time and missing/sensitive settings with separators. Equal field heights and gutters, wrapped labels and responsive columns share the reference layout. Loading is announced once. Export the typed configuration and locale/zone/range/redaction rules.

Value identity

Apply numeric formatting to quantities, not IDs, phone numbers, postal codes or tracking references. Preserve leading zeros. Numeric table alignment applies only to numeric kinds. Date-only values retain their calendar day regardless of time zone. Ranges require two valid ordered dates; partial redaction counts Unicode code points and always masks at least one.

Localized display

Locale controls grouping patterns, currency placement, percent spacing and relative wording. Unit symbols preserve case; SI quantities use a space before the unit. Decimal precision fixes currency fractions and limits other numeric fractions. Display strings are not interchange timestamps. Exports include current valid configuration and specific guidance, not unselected editor options.
