Guidelines · Data Format

Data Format

How numbers, dates, currency and missing values are written for display - one rule per case, so the same value never renders two different ways on two different screens.

Numbers and currency

The same number should read exactly the same way in a table, a card and an export - never spelled out in one place and abbreviated in another for no reason tied to the content.

Thousands separator Comma every three digits - 123,220, never 123220 Rule
Units Lowercase, no space before - 220kg, 12.32% Rule
Currency Symbol or ISO code immediately before the number - £123.00 or GBP 123.00, never after Rule
Large amounts Abbreviate past six figures - 1.2M, 3.4B - full precision stays available on hover or in the export Rule
Tables Right-align numeric columns so digits stack for vertical comparison - never center or left-align a number column Rule

Dates and times

One format per case, chosen for how it's actually read - unambiguous across locales, precise only when precision is asked for, and never a bare time with no time zone for anyone outside it.

Absolute date YYYY-MM-DD (2026-03-14) - all-numeric formats like 03/14/26 are ambiguous across locales Rule
Absolute time 24-hour HH:MM, seconds only when precision genuinely matters (14:08, not 2:08 PM) Rule
Combined Date, space, time - 2026-03-14 14:08 Rule
Relative time "just now" under 1 minute, "N minutes ago" under 1 hour, "N hours ago" under 24, then the absolute date Rule
Time zone Name it whenever a time crosses more than one person's context - a bare time is a guess for anyone not in the same zone Rule
Ranges Both ends spelled out with a dash - 2026-01-01 - 2026-03-31 - never an open-ended "from" with no visible end Rule

Missing and sensitive data

A missing value, a still-loading value and a deliberately redacted value are three different situations - the rendering should make it obvious which one a reader is looking at, never one generic placeholder standing in for all three.

No value An en dash (–) in a table cell or field - never a blank cell, which reads as a loading or rendering failure Rule
Loading A skeleton shaped like the eventual content - never the em dash placeholder, which implies the value is confirmed absent Rule
Full redaction Asterisks in place of the whole value for highly sensitive fields - never a fake plausible-looking value Rule
Partial redaction Preserve enough to identify, mask the rest - a card ending 1402, a name showing first and last letter only Rule

Empty vs. missing vs. loading

These are three different states and need three different treatments - collapsing them into one blank cell or one generic label hides which one the user is looking at.

Do

Renewal date: –

An en dash reads unambiguously as "no value exists" - distinct from a still-loading skeleton and from a genuinely empty list.

Don't

Renewal date: [blank cell]

A blank cell is indistinguishable from a rendering bug or a value still in flight - the user can't tell if something is wrong.

Data Format - Markdown export

Implementation contract

Saved validated choices override project recommendations, which override system defaults. This implementation contract governs static specimens. Resolved tokens in the current export are authoritative values. Component exceptions must name the affected role and reason.

Flow

Configure a field, inspect its formatted example, copy/export current valid settings and reset/reload. Every valid input updates without blur. Invalid simultaneous fields all expose errors and retain the prior valid configuration.

Constraints

Decimal precision 0–6, trailing reveal 0–8, one Unicode code point for the mask, a supported locale and valid IANA zone. Explicit comma grouping cannot conflict with a comma decimal locale. Distinguish real zero, missing, invalid and loading. Never reveal the entire value through a tooltip or accessible name.

Layout and accessibility

Group number/currency, date/time and missing/sensitive settings with separators. Equal field heights and gutters, wrapped labels and responsive columns share the reference layout. Loading is announced once. Export the typed configuration and locale/zone/range/redaction rules.

Value identity

Apply numeric formatting to quantities, not IDs, phone numbers, postal codes or tracking references. Preserve leading zeros. Numeric table alignment applies only to numeric kinds. Date-only values retain their calendar day regardless of time zone. Ranges require two valid ordered dates; partial redaction counts Unicode code points and always masks at least one.
