=== add-on-default.html ===
Create a complete Add-on component system for the Agentic Design System.

An Add-on is a single-line text field with an optional prefix segment and/or suffix segment attached directly to it, sharing one visual control - like a protocol prefix on a URL field or a currency/unit suffix on a price field. Each segment has its own subtle background, distinct from the input area, so it reads as a separate attached zone rather than plain field background.

Build it as ONE reusable component controlled by properties (type, size, radius, state) - not as separate one-off fields for each variant.

Types (3):
- Outlined: The default text field style - a bordered box that works well on any background and reads clearly in dense forms.
  Rest: background:#ffffff;border:1.5px solid rgba(15,15,10,0.15);
  Hover: border-color:#69707D;
  Focused: border-color:#FF031A;outline:2px solid #ff4253;outline-offset:2px; Never just a color change, so layout never shifts.
  Error: border-color:#ff031a; Paired with an inline error message below the field in #ff031a.
- Filled: A softer-emphasis field with a solid background instead of a border, useful when a form sits on a bordered card and an outline would compete visually.
  Rest: background:#f1f1ee;border:1.5px solid transparent;
  Hover: background:#e3e3df;
  Focused: background:#ffffff;border-color:#FF031A;outline:2px solid #ff4253;outline-offset:2px; Never just a color change, so layout never shifts.
  Error: border-color:#ff031a; Paired with an inline error message below the field in #ff031a.
- Underlined: A minimal field with only a bottom border, useful for compact inline forms or search-like inputs where a full box would feel heavy.
  Rest: border-bottom:1.5px solid rgba(15,15,10,0.15);
  Hover: border-bottom-color:#69707D;
  Focused: border-bottom-color:#FF031A;outline:2px solid #ff4253;outline-offset:2px; Never just a color change, so layout never shifts.
  Error: border-bottom-color:#ff031a; Paired with an inline error message below the field in #ff031a.

States (6, apply to every type): Rest, Hover, Focused, Filled, Error, Disabled.
- Filled: same appearance as Rest, showing an entered value instead of the placeholder.
- Disabled: 50% opacity, not-allowed cursor, no hover/focus feedback.

What size do you want? (24px - XXS / 28px - XS / 32px - S / 36px - SM / 40px - M / 44px - L / 48px - XL / 56px - XXL) Padding and font-size scale proportionally with height.

What corner radius do you want? (0px - Sharp / 4px - Compact / 8px - Balanced / 12px - Soft / Full - Pill) Applies to Outlined and Filled - Underlined stays square, matching its minimal style. Segments nest inside the control's own radius on their outer corner only.

Component properties: Label (editable text above the field), Placeholder (editable text shown when empty), Show prefix (boolean, optional text segment attached to the left edge of the field with its own editable prefix text - e.g. a protocol or currency symbol), Show suffix (boolean, optional text segment attached to the right edge of the field with its own editable suffix text - e.g. a domain or unit).



=== affix-default.html ===
Create a complete Affix component for the Agentic Design System.

Build it as ONE reusable component controlled by properties (type, offset, state, content) - a wrapper that pins its child element to the viewport once the page scrolls past the child's original position, so it stays reachable.

Types (2):
- Top: pins the element 8px from the top of the viewport once scrolled past.
- Bottom: pins the element 8px from the bottom of the viewport once scrolled past.

States (3):
- Rest: the element sits in its normal position in the page flow - not yet affixed.
- Affixed: the element is pinned to its edge, visually lifted with a shadow and a slightly stronger border/background so it reads as detached from the page flow beneath it.
- Disabled: affix behavior is turned off entirely - the element always stays in its normal flow position, shown dimmed here to distinguish it from Rest.

Component properties: Content label (text, e.g. "Filter toolbar" - the content being pinned, such as a toolbar or a call-to-action); Offset (number, px from the edge once affixed) - currently 8.



=== alert-default.html ===
Create a complete Alert component for the Agentic Design System.

Build it as ONE reusable component controlled by properties (type, state, radius) - an inline banner/message block embedded in page content (not a floating overlay like Toast), used to surface a status message such as "Your changes have been saved." It sits flush in the page flow, full width of its container, with a colored icon, title, optional description, and optional dismiss/action controls.

Types (4):
- Info: A neutral informational message - status updates, tips, and other non-urgent notices.
  Accent color (icon, title text, left border): #4f8fe6
  Background: #f1f1ee - ONE consistent background across every type, never tinted per type. Left border: 3px solid the accent color. Only the icon, title and left border ever carry the semantic color.
- Success: Confirms a positive outcome - a save, a submit, or another action completing as expected.
  Accent color (icon, title text, left border): #2fbf6e
  Background: #f1f1ee - ONE consistent background across every type, never tinted per type. Left border: 3px solid the accent color. Only the icon, title and left border ever carry the semantic color.
- Warning: Flags something that needs attention before it becomes a problem.
  Accent color (icon, title text, left border): #e6a53a
  Background: #f1f1ee - ONE consistent background across every type, never tinted per type. Left border: 3px solid the accent color. Only the icon, title and left border ever carry the semantic color.
- Error: Reports a failure or invalid state that is blocking progress.
  Accent color (icon, title text, left border): #ff031a
  Background: #f1f1ee - ONE consistent background across every type, never tinted per type. Left border: 3px solid the accent color. Only the icon, title and left border ever carry the semantic color.

States (4, structural - change what's rendered inside the banner, not just its color):
- Default: title and description, no extra controls.
- Dismissible: adds a trailing close (x) icon button.
- With action: adds an inline text-style action button (e.g. "Undo") after the description.
- Title only: title text only - the description is omitted entirely, regardless of whether a description value is set.

What corner radius do you want? (0px - Sharp / 4px - Compact / 8px - Balanced / 12px - Soft / Full - Pill) Applied to the whole banner.

Component properties: Corner radius; Title (text, default "Update available"); Description (text, default "A new version is ready to install.", omitted for the Title-only state); Show icon (boolean, default checked - shows a colored status icon matching the alert's type).
Current values - Title: "Update available", Description: "A new version is ready to install.", Show icon: yes.



=== anchor-default.html ===
Create a complete Anchor (inline text link) component for the Agentic Design System.

Build it as ONE reusable component controlled by properties (type, size, state) - a standalone piece of plain inline navigational text used for wayfinding (e.g. "Learn more", "View documentation"), distinct from Button's boxed "Link"/"Transparent" type, which reads as a boxed call-to-action.

Types (2):
- Standalone: Plain inline text link with no adornment - reads as part of the surrounding copy until it is interacted with.
- With icon: Text plus a trailing external-link arrow icon - signals the link leaves the current context, e.g. an external reference or a documentation link.

States (5, apply to the anchor text - identical across both types):
- Rest: color:#ff4253;text-decoration:none;
- Hover: color:#FF031A;text-decoration:underline;
- Focused: color:#ff4253;text-decoration:none;outline:2px solid #ff4253;outline-offset:2px;border-radius:2px; Never just a color change, so keyboard focus is always visible.
- Visited: color:#d10215; Only a color change is allowed here - browsers block every other CSS property on the real :visited pseudo-class for privacy reasons.
- Disabled: opacity:0.5;cursor:default;pointer-events:none; Anchors have no native disabled attribute, so this is simulated with aria-disabled="true" plus pointer-events:none and reduced opacity - it is not a real browser-level disabled element.

With icon type only: append this trailing external-link arrow SVG after the text with a small gap, sized to roughly match the text's line-height: <svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M7 17L17 7M17 7H7M17 7V17"/></svg>

What size do you want? (12px - XS / 14px - S / 16px - M / 18px - L) Anchors are sized by font-size, not height - the icon (With icon type) scales alongside it.

Component properties: Label (editable text, current value "Learn more").



=== autocomplete-default.html ===
Create a complete Autocomplete component system for the Agentic Design System.

Build it as ONE reusable component controlled by properties (type, size, radius, state) - not as separate one-off fields for each variant. It is a text input that shows a dropdown suggestion panel of matching options below it while the user types or when focused, letting them either pick a suggestion or keep typing a free-form value - distinct from Select (a closed-option picker, no typing) and from a plain Input (no suggestion panel).

Types (2):
- Outlined: The default autocomplete field style - a bordered box that works well on any background and reads clearly in dense forms.
  Rest: background:#ffffff;border:1.5px solid rgba(15,15,10,0.15);
  Hover: border-color:#69707D;
  Focus: border-color:#FF031A;outline:2px solid #ff4253;outline-offset:2px; Never just a color change, so layout never shifts.
  Open: same border/outline treatment as Focus, plus a suggestion panel anchored below the field.
- Filled: A softer-emphasis field with a solid background instead of a border, useful when a form sits on a bordered card and an outline would compete visually.
  Rest: background:#f1f1ee;border:1.5px solid transparent;
  Hover: background:#e3e3df;
  Focus: background:#ffffff;border-color:#FF031A;outline:2px solid #ff4253;outline-offset:2px; Never just a color change, so layout never shifts.
  Open: same border/outline treatment as Focus, plus a suggestion panel anchored below the field.

States (6, apply to every type): Rest, Hover, Focus, Open, Filled, Disabled.
- Focus: real keyboard focus on the field, no suggestion panel visible yet.
- Open: the suggestion panel is visible directly below the field while the user is actively typing - panel content is 3 example option rows, with one visually highlighted as if hovered or keyboard-focused so the user can see which option Enter/click would select.
- Filled: same appearance as Rest, showing an entered value with the suggestion panel closed - the user already picked a value or dismissed the panel.
- Disabled: 50% opacity, not-allowed cursor, no hover/focus/open feedback.

What size do you want? (24px - XXS / 28px - XS / 32px - S / 36px - SM / 40px - M / 44px - L / 48px - XL / 56px - XXL) Padding and font-size scale proportionally with height.

What corner radius do you want? (0px - Sharp / 4px - Compact / 8px - Balanced / 12px - Soft / Full - Pill) Applies to both Outlined and Filled.

Component properties: Label (editable text above the field), Placeholder (editable text shown when empty).



=== avatar-default.html ===
Create a complete Avatar component for the Agentic Design System.

Build it as ONE reusable component controlled by properties (type, size, shape, presence state) - a compact circular (or square) visual identifier for a person, not a one-off image tag.

Content types (3):
- Initials: A colored circle showing the person's 1-2 letter initials - used whenever no photo is available.
- Icon: A colored circle containing a generic person-silhouette icon - a neutral placeholder for an unknown or anonymous person.
- Image: A circle filled with a gradient standing in for an illustrated photo placeholder - real image URLs are never fetched, so this represents where a person's photo would render.

Presence states (4, a small status dot in the bottom-right corner):
- Default: no status dot shown.
- Online: a small green dot.
- Away: a small amber dot.
- Offline: a small gray/dim dot.
These are structural/presentational variants, not interaction states - Avatar itself is not interactive.

Component properties: Size (24px / 32px - default / 40px / 48px, currently 32px - Default - font-size and the status dot scale proportionally with the box size); Shape (Circle / Square, currently Circle); Initials text (Initials type only, currently "JD"). Avatar.Group (a separate composition, not a per-avatar property): a list of Avatars overlapped with negative margin and a border matching the page background, with a Max count past which the final tile becomes a "+N" overflow indicator styled like a real avatar. Show as (Avatars / Names only) - whether the group renders as that overlapping avatar-circle stack, or as a plain vertical list of full names with no avatar graphic at all, for contexts where showing the avatar image isn't worth the space; both modes represent the identical list, including the same "+N" overflow count.



=== badge-default.html ===
Create a complete Badge component for the Agentic Design System.

Build it as ONE reusable component controlled by properties (form, color, size) - a small indicator, not a one-off number or dot hard-coded per screen.

Badge is not interactive - unlike most components in this system, it has no hover, focus or disabled state. Its variation is purely structural: 3 forms, each in 4 semantic colors, each in 2 sizes.

Forms (3):
- Count: a small numeric pill overlaid on the top-right corner of a host element (an icon or button). Shows the current Count value, capping the display at "99+" once Count exceeds the configured Max count.
- Dot: a small plain dot overlaid on the top-right corner of a host element, with no number - just signals "there's something new".
- Status: an inline dot plus a text label (e.g. "Active"), used standalone rather than overlaid on anything.

Colors (5, apply to every form, matching Ant Design's own Status Badge set): Default (var(--red-500), this system's brand red), Success (var(--green-500)), Processing (var(--blue-500), pulses with an expanding-ring animation to signal something actively in progress), Warning (var(--amber-500)), Error (var(--danger-500)).

What size do you want? (Default / Small) Small drops the Count pill to 16px/10px font and the Status dot+label to match - the host icon and every color stay identical at either size.

Component properties: Count (number, applies only to the Count type) - currently 5. Max count (number, applies only to the Count type, caps the displayed value at "N+" once Count exceeds it) - currently 99. Status label (string, applies only to the Status type) - currently "Active".



=== breadcrumb-default.html ===

Component properties: Labels (comma-separated editable text, one per breadcrumb item, current value "Home, Products, Shoes" - item count follows the number of labels entered). The last label is always rendered as the current page (a non-link span); every earlier label is a real link.



=== button-destructive.html ===
Create a complete Button component system for the Agentic Design System.

Build it as ONE reusable component controlled by properties (type, size, content, radius, state) - not as separate one-off components for each variant.

Types (8):
- Primary: The button that carries the main call to action on a screen, like saving a form, submitting a purchase, or confirming a change.
  Rest: background:var(--button-primary-bg-default);color:var(--button-primary-text-default);
  Hover: background:var(--button-primary-bg-hover);color:var(--button-primary-text-hover);
  Pressed: background:var(--button-primary-bg-active);color:var(--button-primary-text-active);

  Pressed: background:#f1f1ee;

  Hover: background:#f1f1ee;
  Pressed: background:#e3e3df;
- Ghost: An action placed inside toolbars, cards, or dense layouts where a bordered button would add unnecessary weight, like closing or dismissing something.
  Rest: background:transparent;color:#4B5563;
  Hover: background:#f1f1ee;color:#111827;
  Pressed: background:#e3e3df;
- Neutral: An action that needs clear affordance without strong brand emphasis, like filtering, sorting, or opening options.
  Rest: background:#f1f1ee;color:#111827;border:1.5px solid rgba(15,15,10,0.15);
  Hover: background:#e3e3df;
  Pressed: background:#fbfbfa;
- Link: A navigation-style action that behaves like a hyperlink rather than a boxed command, like viewing details or opening a page.
  Rest: background:transparent;color:#ff4253;padding-inline:var(--space-8);
  Hover: text-decoration:underline;
  Pressed: color:#d10215;
  Focus: 2px outline in #ff4253, 3px offset, 4px corner radius on the outline.
- Approve: An action that confirms or approves something positive, like approving a request or accepting a change.
  Rest: background:rgba(47,191,110,0.1);color:#2FBF6E;border:2px solid #2FBF6E;
  Hover: background:rgba(47,191,110,0.16);
  Pressed: background:rgba(47,191,110,0.26);
  Focus: 2px outline in #2fbf6e (fixed approve color, not the brand color), 2px offset.
- Delete: An action with irreversible consequences, like deleting a record or discarding unsaved work.
  Rest: background:rgba(255,3,26,0.1);color:#FF031A;border:2px solid #FF031A;
  Hover: background:rgba(255,3,26,0.16);color:#FF3F4F;border-color:#FF3F4F;
  Pressed: background:rgba(255,3,26,0.26);color:#D80016;border-color:#D80016;
  Focus: 2px outline in #ff031a (fixed danger color, not the brand color), 2px offset.

States (5, apply to every type): Rest, Hover, Pressed, Focus, Disabled.
- Focus (default, see per-type exceptions above): 2px outline in #ff4253, 2px offset - never just a color change, so layout never shifts.
- Disabled: 40% opacity, not-allowed cursor - except Primary at 45% opacity, and Link additionally drops its underline.

What size do you want? (24px - XXS / 28px - XS / 32px - S / 36px - SM / 40px - M / 44px - L / 48px - XL / 56px - XXL) Padding and font-size scale proportionally with height.

What content do you want? (Text only / Icon left / Icon right / Icon both sides / Icon only) Icon only requires an accessible label for screen readers (e.g. aria-label), since there is no visible text.

What corner radius do you want? (0px - Sharp / 4px - Compact / 8px - Balanced / 12px - Soft / Full - Pill) Applied uniformly across every type.

It is a multi-line free-form text field for longer content like comments, descriptions, or messages - it grows taller through a Rows property, not by manual dragging (resize: none, matching this system's other fields, which don't offer manual resize).

Types (3):
- Outlined: The default text area style - a bordered box that works well on any background and reads clearly in dense forms.
  Rest: background:#ffffff;border:1.5px solid rgba(15,15,10,0.15);
  Hover: border-color:#69707D;

  Error: border-color:#ff031a; Paired with an inline error message below the field in #ff031a.
- Filled: A softer-emphasis field with a solid background instead of a border, useful when a form sits on a bordered card and an outline would compete visually.
  Rest: background:#f1f1ee;border:1.5px solid transparent;
  Hover: background:#e3e3df;
  Focused: background:#ffffff;border-color:#FF031A;outline:2px solid #ff4253;outline-offset:2px; Never just a color change, so layout never shifts.
  Error: border-color:#ff031a; Paired with an inline error message below the field in #ff031a.
- Underlined: A minimal field with only a bottom border, useful for compact inline forms where a full box would feel heavy.
  Rest: border-bottom:1.5px solid rgba(15,15,10,0.15);

  Focused: border-bottom-color:#FF031A;outline:2px solid #ff4253;outline-offset:2px; Never just a color change, so layout never shifts.
  Error: border-bottom-color:#ff031a; Paired with an inline error message below the field in #ff031a.

- Filled: same appearance as Rest, showing entered multi-line text instead of the placeholder.
- Disabled: 50% opacity, not-allowed cursor, no hover/focus feedback.

What size do you want? (24px - XXS / 28px - XS / 32px - S / 36px - SM / 40px - M / 44px - L / 48px - XL / 56px - XXL) Padding and font-size scale proportionally - Size controls the field's padding/font-size only, never its visible height.

What corner radius do you want? (0px - Sharp / 4px - Compact / 8px - Balanced / 12px - Soft / Full - Pill) Applies to Outlined and Filled - Underlined stays square, matching its minimal style.

Component properties: Label (editable text above the field), Placeholder (editable text shown when empty), Rows (2-8, default 4, controls the field's visible height - the number of text lines tall it renders).

Create a complete Toast (floating notification) component for the Agentic Design System.

Build it as ONE reusable component controlled by properties (type, state, radius) - a floating, elevated notification card (solid background, border, drop shadow, fixed ~340px max-width) that appears temporarily to confirm an action or report a status.

It differs from Alert by being a floating overlay element, not inline page content - in production it is typically rendered in a fixed screen corner (e.g. bottom-right), stacked above the page, rather than embedded in the content flow the way Alert is.

Types (4, drive only the icon color - the card itself always stays a solid neutral elevated surface):
- Info: Neutral, informational status update - nothing succeeded or failed, it's just worth surfacing. Icon color: color:#4f8fe6;

- Error: Reports that an action failed. Icon color: color:#ff031a;

States (4, structural, apply to the whole card):
- Default: title and description only, no extra controls.
- Dismissible: adds a trailing close (x) icon button in the card's top-right corner.
- With action: adds an inline text-style action button (e.g. "View") below the description.
- With progress: adds a thin colored progress/timer bar along the card's bottom edge, using the type's accent color at roughly 60% width to suggest a countdown in progress.

What corner radius do you want? (0px - Sharp / 4px - Compact / 8px - Balanced / 12px - Soft / Full - Pill) Applied to the whole card, with matching inset on the bottom edge so the With-progress bar never pokes out past rounded corners.

Component properties: Title (text, default "Upload complete"); Description (text, default "your-file.pdf was uploaded successfully."); Show icon (boolean toggle, default on - shows the semantic type icon beside the title/description).
Current values - Title: "Upload complete", Description: "your-file.pdf was uploaded successfully.", Show icon: yes.

=== tree-default.html ===
Create a complete Tree component for the Agentic Design System.

Build it as ONE reusable component controlled by properties (type, root label, icon visibility, state) - a standalone, always-visible hierarchical structure with expandable branches, like a file system or an org chart. Distinct from Tree Select, which hides the same structure behind a Select-style dropdown trigger.

Types (3):
- Default: nodes are selectable by click - clicking a node highlights it, no checkboxes.
- Checkable: every node gets its own checkbox for multi-select; checking a parent should check all its children (and check a parent automatically when every child becomes checked).
- Metatext: same selectable nodes as Default (no checkboxes), plus a second, smaller line of muted supplemental text under each node's label (a file size, an item count) - useful for disambiguating similarly-named nodes or surfacing a quick detail without adding a column. Modeled on Lightning Design System's Tree item metatext, which top-aligns the toggle/icon against the now-taller two-line row rather than centering it.

States (4):
- Default: top-level nodes visible, all branches collapsed.
- Expanded: one branch expanded, showing its children.
- Selected: one leaf node highlighted (Default type) or checked (Checkable type), with its parent branch expanded so it's visible.
- Disabled: the whole tree dimmed and non-interactive.

Each node is either a parent (has children, shown with an expand/collapse chevron and a folder icon) or a leaf (shown with a file icon). Clicking a parent's chevron toggles its children's visibility without selecting it.

Component properties: Root label (text, a heading shown above the node list, e.g. "Documents"); Show icons (boolean, toggles the folder/file icon next to each node) - currently on.



=== tree-select-default.html ===
Create a complete Tree Select component system for the Agentic Design System.

Build it as ONE reusable component controlled by properties (type, size, radius, state) - not as separate one-off fields for each variant. It is a select-like trigger field showing a selected node's label (e.g. "Engineering / Frontend") with a trailing chevron icon, that opens a floating panel below it containing an INDENTED, EXPANDABLE TREE of options - parent nodes with a collapse/expand caret, child nodes indented beneath them, any node at any depth selectable, not just leaves. Distinct from Select (one flat list) and from Cascader (fixed side-by-side columns, one per level) - a Tree Select's hierarchy can be any depth and stays in a single scrolling list with indentation showing nesting.

Types (2):
- Outlined: The default tree select field style - a bordered box that works well on any background and reads clearly in dense forms.
  Rest: background:#ffffff;border:1.5px solid rgba(15,15,10,0.15);
  Hover: border-color:#69707D;
  Focus: border-color:#FF031A;outline:2px solid #ff4253;outline-offset:2px; Never just a color change, so layout never shifts.
  Open: same border/outline treatment as Focus, plus an indented tree panel anchored below the field.
- Filled: A softer-emphasis field with a solid background instead of a border, useful when a form sits on a bordered card and an outline would compete visually.
  Rest: background:#f1f1ee;border:1.5px solid transparent;
  Hover: background:#e3e3df;
  Focus: background:#ffffff;border-color:#FF031A;outline:2px solid #ff4253;outline-offset:2px; Never just a color change, so layout never shifts.
  Open: same border/outline treatment as Focus, plus an indented tree panel anchored below the field.

States (6, apply to every type): Rest, Hover, Focus, Open, Filled, Disabled.
- Focus: real keyboard focus on the field, no tree panel visible yet.
- Open: the tree panel is visible directly below the field - each row is indented by depth (16px per level), parent nodes show a caret (down when expanded, right when collapsed) before the label, leaf nodes show a same-width blank spacer instead so every label still aligns in a column, and the currently selected node is highlighted.
- Filled: same appearance as Rest, showing the selected node's label with the panel closed.
- Disabled: 50% opacity, not-allowed cursor, no hover/focus/open feedback.

What size do you want? (24px - XXS / 28px - XS / 32px - S / 36px - SM / 40px - M / 44px - L / 48px - XL / 56px - XXL) Padding and font-size scale proportionally with height.

What corner radius do you want? (0px - Sharp / 4px - Compact / 8px - Balanced / 12px - Soft / Full - Pill) Applies to both Outlined and Filled.

Component properties: Label (editable text above the field), Placeholder (editable text shown when empty). Multiple selection (boolean - replaces the single active-row highlight with a real checkbox per node, parents included, letting more than one node be picked across branches). Search (boolean - a real input inside the trigger itself, narrowing the tree to matching nodes with the matched substring highlighted).
