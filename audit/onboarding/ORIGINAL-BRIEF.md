I want you to thoroughly review and optimize the entire Onboarding Flow and Overview screen.

Currently, the onboarding experience is not properly structured, and several user flows and task flows are incomplete, unclear, or not logically connected.

IMPORTANT:
Do not focus only on visual/UI improvements. Review the complete UX, including Information Architecture, User Flow, Task Flow, Interaction Design, Content Hierarchy, CTA logic, Empty States, Success States, Error States, and overall usability.

==================================================
1. NEW PROJECT ONBOARDING FLOW
==================================================

On the Overview screen, there should be a clear primary CTA:

"Create a New Project"

When a new user clicks this CTA, open a modal/popup for project creation.

The modal should contain:

- Project Name
- Your Name
- Email Address
- Select Your Role

Role options should be clearly defined.

If the user selects "Other" as their role:
→ Display an additional field:
"Job Title"

The Job Title field should only appear when "Other" is selected.

After completing all required information, the user clicks:

"Generate Link"

==================================================
2. LINK GENERATION
==================================================

After the user clicks "Generate Link", generate the required project resources/links for:

- CSS Variables
- NPM Package
- Figma Library

The generated links should be clearly presented and easy to understand.

The user should be able to:

- Copy the link
- Open/access the resource
- Share the link
- Invite another person
- Understand what each link is for
- See the current status of the generated resource

Do not overwhelm the user with too much information immediately after project creation.

Use a clear hierarchy and progressive disclosure where appropriate.

==================================================
3. PROJECT LINK HISTORY
==================================================

Users should be able to access their previously generated project links.

Create a clear:

"Project Link History"

section/page/panel.

Users should be able to see:

- Project/resource name
- Resource type
- Generated date
- Generated by
- Current status
- Share option
- Copy option
- Open/access option

The history should make it easy for users to understand which links were previously generated.

==================================================
4. SHARING AND INVITING USERS
==================================================

Users should have a clear way to share a project with someone else.

Provide an appropriate:

"Share Project"

and/or

"Invite Members"

action.

The user should be able to:

- Share a project link
- Invite another user/team member
- Enter the invitee's email address
- Understand what access the invited person will receive
- See whether an invitation is pending, accepted, or expired
- Resend an invitation when required

Make sure sharing and inviting are not confusingly mixed with link generation.

==================================================
5. OVERVIEW SCREEN AUDIT
==================================================

Thoroughly review EVERY element on the Overview screen.

Check:

- Page structure
- Information Architecture
- Navigation
- Primary and secondary CTAs
- Project creation flow
- Project status
- Empty states
- Existing project states
- Link generation
- Link history
- Sharing
- Invitations
- User roles
- Notifications
- Success states
- Error states
- Loading states
- Confirmation states
- Permissions
- Search/filter/sort where relevant
- Responsive behavior
- Accessibility
- Microcopy
- Interaction patterns
- Visual hierarchy

Identify anything that is:

- Confusing
- Redundant
- Unnecessary
- Missing
- Inconsistent
- Difficult to understand
- Difficult to discover
- Not logically connected
- Creating unnecessary steps
- Creating cognitive load

==================================================
6. USER FLOW
==================================================

The ideal high-level flow should be:

Overview
↓
Create a New Project
↓
Enter Project Information
↓
Select User Role
↓
If "Other" → Enter Job Title
↓
Generate Link
↓
Project Created Successfully
↓
View Generated Resources
↓
CSS Variables / NPM Package / Figma Library
↓
Copy / Open / Share
↓
Invite Users if Required
↓
View Project Link History

Make sure the actual interface supports this flow naturally.

==================================================
7. FIRST-TIME USER EXPERIENCE
==================================================

Think specifically about a completely new user who has never used the platform before.

The user should immediately understand:

- What this platform is
- What they need to do first
- What a Project represents
- Why they need to create a Project
- What information they need to provide
- What happens after clicking "Generate Link"
- What CSS Variables, NPM Package, and Figma Library represent
- How they can share the project
- How they can invite other people
- Where they can find previously generated links

Avoid forcing users to understand the entire system before completing their first task.

==================================================
8. EMPTY STATE
==================================================

If the user has no projects yet, the Overview screen should have a strong empty state.

The empty state should clearly communicate:

- There are currently no projects
- What a project is
- Why the user should create one
- The primary action

Example structure:

"No projects yet"

"Create your first project to generate and manage your design system resources."

Primary CTA:

"Create a New Project"

Do not add unnecessary secondary actions that distract from the first task.

==================================================
9. SUCCESS STATE
==================================================

After project creation and link generation, provide a clear success state.

The user should understand:

- Project creation was successful
- Links/resources were generated successfully
- What they can do next

Provide relevant actions such as:

- Copy
- Open
- Share
- Invite Members
- View Project
- View Link History

==================================================
10. ERROR AND LOADING STATES
==================================================

Define appropriate states for:

- Generating a project
- Generating links
- API/network failure
- Invalid information
- Duplicate project name
- Failed resource generation
- Expired links
- Permission issues
- Failed invitations

Do not leave users wondering whether an action worked.

Every asynchronous action should have an appropriate:

Loading → Success / Error

state.

==================================================
11. UX PRINCIPLES
==================================================

Optimize the experience using these principles:

1. Clear hierarchy
2. Progressive disclosure
3. Minimal cognitive load
4. Predictable interactions
5. Consistent CTA behavior
6. Strong feedback after every important action
7. Clear system status
8. Accessibility-first design
9. Scalable information architecture
10. Enterprise-grade usability

Follow WCAG 2.2 AA principles where applicable.

==================================================
12. DESIGN SYSTEM CONSISTENCY
==================================================

Do not introduce random new UI patterns.

Use the existing Design System components, spacing, typography, colors, buttons, inputs, dropdowns, modals, notifications, and interaction states wherever possible.

If an existing component is insufficient, identify the gap and propose a reusable component rather than creating a one-off solution.

==================================================
13. IMPORTANT: DO NOT JUST REDESIGN THE SCREEN
==================================================

I want you to think like a Senior UX/Product Designer.

First understand the existing product structure.

Then:

1. Audit the current Overview screen.
2. Identify UX problems.
3. Identify missing user/task flows.
4. Identify unnecessary steps.
5. Define the ideal information architecture.
6. Define the end-to-end user journey.
7. Define the improved task flow.
8. Define all important states.
9. Then implement the improved UI/UX.

Do not simply move elements around visually.

==================================================
14. FINAL EXPECTATION
==================================================

The final experience should make the following journey extremely clear:

"New user → Create Project → Provide information → Generate resources → Access resources → Copy/Open/Share → Invite users → Manage project → View link history"

The Overview screen should work as the central hub for this entire journey.

Review and fix the complete flow rather than only fixing individual UI elements.

If you identify a better UX approach than the flow described above, propose it first and explain why it is better before implementing it.

The final result should feel like a polished, scalable, enterprise-grade Agentic Design System platform.
