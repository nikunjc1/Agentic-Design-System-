Owner: Design System Team · Version: v3.4.0 · Changelog: not yet tracked

Markdown is the AI-readable context layer, not the source of truth. Export must be budget-aware (a full enterprise system exceeds any model's usable context) and reproducible (an old version's export must always return exactly what was handed to an agent at the time, never today's template applied to old data).

  • Token estimates are mandatory, shown before download - handing someone a file that silently overflows their model's context is the most common failure mode of design-system MD exports.
  • Structure: single file, or a modular folder (.zip). Format: Markdown, JSON, or YAML.

project: InsureEdge 3.0
version: 3.2.0
generated: 2026-09-23T14:20:00Z
generated_by: Agentic Design System
scope: entire-design-system
tier: T1
source_version_id: v_9f2c41
checksum: sha256:a4f91c2e...
token_estimate: 15200
---

All values dynamic. source_version_id and checksum let a consuming agent detect that its context is stale - without them, versioned MD provides no more safety than a copied paragraph.

Immutability rule

Critical

At every publish, the full MD snapshot is generated and stored as an immutable artefact keyed to the version ID. Exporting from History always serves the stored snapshot, never a fresh regeneration - a corrected export produces a new patch version, snapshots are never mutated. Without this, "export the MD for version 3.0.0" would silently return today's template applied to old data.

Exporting from the current unpublished working state is labelled 3.3.0-draft and marked not reproducible.
