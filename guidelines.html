Component Guidelines

Which component to reach for, by domain - the layer above an individual component's own page, for the moment before you've picked one yet.

Feedback - which one, when

Five components exist for reporting something to the user. Picking the wrong one either interrupts a task that didn't need interrupting, or lets something important scroll past unread.

Toast Confirms something the user just did, on their own timeline, gone in a few seconds toast.html
Notification Reports an event the user didn't initiate - a background job finishing, another user's action notification.html
Alert A persistent, page-level condition that stays until the situation changes or is dismissed alert.html
Modal A decision that must be made before the user can continue, with real consequences modal.html
Pop Confirm A single yes/no question anchored to the control that triggered it - lighter than a Modal pop-confirm.html
Result The end state of a completed flow - success, failure, or an outcome the user needs to act on next result.html

Navigation - which one, when

Getting from one place to another, or showing where the user already is, without more machinery than the situation needs.

Tabs A handful of parallel views over the same object, switched without a page load tabs.html
Breadcrumb Where the current page sits inside a hierarchy the user can step back up through breadcrumb.html
Anchor Position within one long page - a reading-progress indicator, not a hierarchy anchor.html
Steps Position within a multi-step process the user is actively completing, in order steps.html
Pagination Position within a large result set split across pages pagination.html
Menu / Dropdown A list of actions or destinations chosen from, not a record of position menu.html

Data Entry - which one, when

The input should match the shape of the answer the user already has - not the shape that's easiest to build.

Select One choice from a short, flat, known list, all visible at once when open select.html
Autocomplete Free text narrowed by real matches as the user types - for large or open-ended option sets autocomplete.html
Cascader / Tree Select A choice that genuinely nests two or more levels deep - not a flat list dressed up cascader.html
Radio 2-5 mutually exclusive options, all visible, no need to open anything radio.html
Checkbox Independent yes/no choices, any number of which can be true at once checkbox.html
Switch A setting that takes effect immediately - never paired with a separate Save step switch.html
Slider An approximate, eyeballed value - pair with Number whenever the exact figure matters slider.html
Date Range Two dates that must stay logically ordered - one control, not two independent Date Pickers date-range.html

Data Display - which one, when

Showing a set of records or values in the shape the reader actually needs to act on them.

Table Multiple comparable attributes per row - sortable, filterable, scannable by column table.html
List One event or record per row, each with an actor and a specific object - not comparable columns list.html
Description A record's fixed label/value pairs laid out for reading, not comparing across rows description.html
Card One self-contained subject, clickable as a single unit card.html
Timeline Events in chronological order where sequence and pacing both matter timeline.html
Statistic One headline number with the trend that gives it meaning statistic.html
Empty The deliberate zero-results state of any of the above - always says why, never just "No data" empty.html

Button - hierarchy in one row

Every screen should have at most one Primary. Everything else is there to make the choice between actions legible, not to compete with it.

Primary The one action this screen exists to let the user complete - exactly one per view button-primary.html
Secondary A real alternative to Primary, never a destructive or high-stakes action undersold button-secondary.html
Tertiary / Ghost / Link Lowest-emphasis actions - view history, dismiss, inline text links button-tertiary.html
Destructive Reserved for actions that actually destroy something - paired with an easy way out button-destructive.html
Neutral Toolbar-weight actions (filter, sort) that shouldn't pull focus from the content button-neutral.html

Data List - grouping and density

Long lists fail by hiding structure (everything looks the same) or by adding structure the data doesn't have (fake grouping, arbitrary dividers).

Group only real boundaries A Divider or section header marks an actual change in category - not every N items for rhythm divider.html
Prefer built-in density over shrinking text Compact mode reduces padding and row height, not font size - shrinking text just makes it harder to read guidelines.html
Show total + position Pagination states the result count; Table headers stay pinned on scroll so context never gets lost pagination.html
One truncation rule per column The same field is capped at the same width everywhere it's listed - not wider on this screen, narrower on that one table.html
