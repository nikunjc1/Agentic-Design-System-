Design System · Design Values

Design Values

Four values this system is built to hold, and the rule to fall back on when a new decision doesn't fit anything documented yet - trace it back to one of these before inventing something new.

The four values

Every rule elsewhere in this system - the overflow caps, the RTL mirroring, the Do/Don't pairs, the Machine View JSON - exists to serve one of these four. When a new decision doesn't fit an existing rule, trace it back to one of these before inventing something new.

01

Legible

A screen should be readable in one pass, by a person and by a model. Truncation always shows an indicator. Empty states always say why they're empty. Status is never carried by color alone. If understanding a screen requires hovering, waiting, or already knowing the answer, it has failed this value.

02

Consistent

The same problem gets the same answer everywhere it appears. One elevation system, one spacing scale, one way to write a destructive confirmation. A designer or an AI generator should be able to predict an unfamiliar component's behavior from a familiar one, correctly, most of the time.

03

Honest

Nothing in the interface claims more than is true. A progress bar shows a real fraction or doesn't appear. A shadow signals real elevation, not decoration. An animation is justified by what it communicates, not by how it looks. A default value is never silently substituted for a real one without saying so.

04

Adaptive

The system bends to the context it's rendered in rather than assuming one - light or dark, left-to-right or right-to-left, cozy or compact, a human reading it or a model generating from it. Adaptation is built into the component, not bolted on as a special case later.

Where each value shows up

Not abstractions - each of these already governs specific, checkable rules already shipped in this system.

Legible Overflow caps with real ellipsis (not silently-inert ones on flex children), empty-value fallback text, status badges, the 63-component Do/Don't library Enforced
Consistent One motion-token scale, one elevation system with named semantic layers, one spacing rhythm, shared -demo-* class conventions across every component driver Enforced
Honest Shadow philosophy ("never decoration"), Progress never parked at a fake percentage, reduced-motion respected, no dark-pattern copy patterns Enforced
Adaptive Live theme/direction/density toggles on every page, RTL icon mirroring, Human View / Machine View JSON per component Enforced

What this is not

Values are a tiebreaker, not a style. When two of them pull in different directions - Legible wants more label text, Consistent wants the same 220px cap everyone else gets - the fix is almost always to shorten the content, not widen the exception. Reach for a genuinely new rule only when no existing one, correctly applied, gets you there.
